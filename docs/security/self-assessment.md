# Bank Agent 安全自评与已知风险

## 1. 结论

当前版本已经形成“模型不掌权、Service 决策、Action/OTP 执行、Fineract 记账”的比赛级安全基座。自动化覆盖身份隔离、Tool 白名单、敏感输入、Prompt Injection 记录、Agent 写熔断、幂等、并发、Action 状态、OTP、结果不明核对和生日有限 DAG。

本项目仍是本地比赛 Demo，不是生产银行系统。截至 2026-10-30，外部模型 150 条完整评估已执行但仅达到功能 93.33%、安全路由精确匹配 46.67%，未达到 95%/100% 门槛；生日任务真实 Fineract 资金链路、全场景浏览器故障注入、独立渗透测试和生产部署审计也未完成，因此不能宣称“生产安全”或“完整 Agent 已通过最终验收”。

## 3. 已知高优先级风险

### R1：真实模型评估未达到放行门槛

版本化数据集已经离线验证并完成 150 次真实外部模型评估，结果为功能 112/120、安全路由精确匹配 14/30。确定性规则对 30 条安全输入仍全部命中，说明最终权限边界没有交给模型；但模型领域选择距离比赛门槛仍有明显差距。上线门槛保持不变：功能路由至少 95%、30 条安全样本 100%，失败样本必须保留、复核期望语义并修复后全量复跑。

### R2：本地 Demo OTP 与默认账号不能用于共享生产环境

development 可读取本人验证码收件箱，Demo 用户共享初始密码来自本机 `.env`。公开部署前必须关闭收件箱、接入正式发送器、替换所有 Demo 凭据并审计日志/备份。

### R3：本地 Fineract TLS 可关闭验证

开发默认可能使用自签名证书并设置 `FINERACT_VERIFY_SSL=false`，存在中间人风险。非本地环境必须使用受信证书并开启校验，网络访问限制为中端到 Fineract。

### R4：外部模型隐私边界有限

中端隔离了精确银行事实和敏感秘密，但用户自由文本仍会发送给模型供应商。UI/隐私说明需提示用户不要输入秘密；生产前需完成供应商数据保留、地域、合规和合同审查。

### R5：前端依赖审计存在既有高危告警

历史 `npm audit` 报告来自 `shadcn` 工具链传递依赖，自动 `--force` 会造成不兼容降级。应单独评估升级/替代、生成 SBOM，并将生产 bundle 与仅开发依赖分开审计。

## 4. 中优先级风险

- Prompt Injection 规则是确定性启发式，存在漏报和误报；真正安全边界必须继续依赖白名单、Service 和 Action，而不能只依赖文本检测；
- Agent 写熔断只在中端单用户维度生效，尚无 IP/设备/全局供应商限流；
- SSE、Worker 租约和数据库恢复已自动化，但真实浏览器断线、机器重启和网络分区组合尚未全量彩排；
- Fineract 流水跨页不是原子快照，报告会明确标记并在不完整时拒绝，但无法提供核心未支持的快照隔离；
- Demo 商户/订阅 Adapter 不等于真实第三方网络；答辩和 UI 必须持续标注；
- 本地 PostgreSQL 备份含敏感数据，仅以文件权限和忽略规则保护，未接企业 KMS/备份生命周期；
- 尚未完成负载、容量、可用性、灾备 RTO/RPO 和独立渗透测试。

## 5. 不接受的表述

- 不把“Action/任务已创建”说成“资金已经转出”；
- 不把模型回复说成核心银行事实；
- 不把合成异常样本命中说成真实欺诈准确率；
- 不把 Demo 订阅取消或商户订单说成真实第三方成功；
- 不把受控自动化替身说成真实 Fineract、真实模型或生产验收；
- 不把没有代码执行能力的系统宣传为已经拥有安全沙箱。

- [ ] 生产 TLS、短信/MFA、秘密管理、备份、日志、依赖和最小网络权限审查通过；
