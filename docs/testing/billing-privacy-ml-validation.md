## 实现与数据边界

```text
HTTP message/query_context
  → 账户编号占位化 → 路由模型 → 中端领域白名单
  → 中端鉴权并生成请求级 account_ref → 执行模型提出 Tool 参数
  → Service 完整分页/分类/计算/检测
  → AnalysisResult 精确快照（本地 PostgreSQL，默认 24 小时）
      ├→ ModelSummary 白名单 → ToolMessage → 模型只选结论码 → 中端模板文字
      └→ ANALYSIS_READY {analysis_id, kind} → 前端单独 GET → 精确结果卡
```

保持 HTTP 请求 `message/query_context`；返回 `trace_id/message/events`。Tool 名称不变，洞察模型参数改为必填 `account_ref: string | null` 与日期：引用只对当前请求有效，中端映射并再次鉴权；null 明确表示本人全部合格账户。界面 ID 不进入系统 Prompt，按钮问题中的账户编号在路由前也被占位化。明确文字账户先在中端解析/校验再建立引用；歧义或缺范围仍需用户补充，不能擅自扩大到全部账户。

精确金额、数量、占比、自定义分类名、商户、备注、原始账户/交易引用、特征及分数均不进入 ToolMessage、AgentState、事件或模型检查点。请求级收集器只持有安全摘要和引用，不持有精确载荷。没有新增持久化 checkpointer 或多轮记忆。路由与执行模型的银行链路局部关闭全量外部 tracing 和回调，不改变用户全局环境；审计只含 trace、域、工具名、不透明引用/日期、状态等必要元数据，异常只记录类型。两个演示探针默认也只输出安全摘要，并在成功/失败时撤销自身会话。

用户自己输入的原始金额、备注等仍可能发送给模型理解；此改造不声称保护用户主动输入的敏感文本，也不提供差分隐私保证。后续新增 Tool、回调或日志必须复用该隔离契约。

## 摘要策略与精确接口

- `ModelSummary` 严格限制为 `analysis_id/kind/status/insight_codes/main_category`，Pydantic 禁止额外字段；结论码及通用类别码为后端固定词表。
- 任何样本量都不输出精确金融数值。类别概况要求至少 5 笔消费且相应类别至少 5 笔；自定义名称映射为 `OTHER`，不转发原名。
- 非完整自然月只返回通用完成/受限状态。按上海日期计算每日范围预算，类型/排序后账户集合/起止日期规范化；前 10 个不同范围可按样本策略生成摘要，其后只给通用状态。同一范围已受限时当天不能通过重复请求升级摘要。
- 最终模型只提议实际出现的结论码，HTTP 由确定性模板渲染。不合规自由文本、额外金额、欺诈断言均不透传；模型未调用 Tool 时也不能声明银行事实。
- `GET /api/agent/analyses/{analysis_id}` 返回 `{analysis_id, kind, created_at, expires_at, data}`。要求 Bearer、归属及当前账户权限；跨用户/未知引用 404，本人已过期但尚未物理清理的结果 410；成功、认证与错误响应均 `Cache-Control: no-store`。
- 快照与成功审计同事务提交，失败回滚。结果独立于 `BillReport`；维护 CLI 删除过期快照后，再访问已清理 ID 为 404。结果读取不会自动扩大访问权。
- 原统计/报告精确数据不变。异常默认单账户列表、全账户对象保持兼容；`include_metadata=true` 可选返回统一包装与检测状态，现有业务页使用此选项。

## 检测与模型生命周期

保留 `LARGE_V1`、`DUPLICATE_V1` 和已有核实键/状态，增加 `IFOREST_V1` 行为偏离候选。同一单笔交易被规则和模型共同命中时合并来源，保留旧候选键；跨账户交易使用账户/交易复合引用，不混淆相同交易 ID。

仅消费、非撤销流水建模；复用 `TransactionService` 的授权、完整分页及资金语义，排除本人互转和定存本金划转。没有小时、设备、位置或同日交易次序特征。金额 log1p、星期 sin/cos、个人/类别历史中位数偏离、前 7/30 天次数、类别频率、消费日期间隔和历史不足标志按完整日期批次计算；历史只含严格早于当日且前 90 天的交易，同日不能互相作为历史。

维护 CLI 按内部用户 UUID 和 `--as-of` 训练，截止日不计入。训练窗口 180 天，额外预热 90 天；至少 100 笔、30 个不同日期，并按日期顺序分成训练/校准（至少 80/20），不足不发布。个人模型由该用户的单账户/全账户查询共同使用，查询范围仍分别鉴权。参数为 100 棵树、`max_samples=auto`、`contamination=auto`、`random_state=42`、`n_jobs=1`。负 `score_samples` 为异常程度，校准第 95/99 百分位为初始候选/较强偏离阈值；不能解释为欺诈概率。[IsolationForest 官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html)

模型登记用户、窗口、分类配置、特征/依赖版本、阈值、文件名和 SHA-256；查询只选择截止日不晚于查询开始日的最新登记记录。相对查询开始日超过 90 天、配置/账户变化、版本不兼容、无模型、样本不足、工件校验或推理失败时明确回退 `rules_only`，不能宣称机器学习已检测或保证交易安全。对话只加载/推理，不训练或自动更新。

工件只能来自配置的受控目录、UUID `.skops` 文件；校验路径越界/符号链接、20MB 大小上限、SHA-256、固定信任类型和精确估计器类型。固定信任 `sklearn.tree._tree.Tree` 是当前锁定版本发布模型所需的已审阅组件，不根据文件返回的未知类型自动授权。禁止外部 Pickle。目录/文件按 700/600 创建；维护人员应限制目录写权限。训练与服务锁定相同数值依赖，改变版本需重训。[模型持久化安全说明](https://scikit-learn.org/stable/model_persistence.html)
