# Agent 核心算法与确定性策略

## 1. 设计原则

Agent 使用“概率理解 + 确定性执行”：模型处理自然语言、领域候选、澄清和 Tool 参数；中端处理身份、资源归属、风险、确认、OTP、幂等、状态机、执行和核对。任何模型输出都不能直接修改银行状态。

## 2. 两阶段领域与工具选择

第一阶段，路由模型只返回最多三个领域候选。中端验证候选属于注册表、当前允许集合和独占规则；订阅与生日编排必须单独请求。无关或不支持请求得到空领域，不让模型自由启用能力。

第二阶段，中端只为获准领域组合 `BASE_PROMPT + DOMAIN_PROMPT + DOMAIN_TOOLS`。LangGraph 每轮最多累计三个 Tool 调用，验证工具名、参数 Schema、写操作安全锁和混批限制。Tool 只能访问请求级 `AgentContext` 中注入的 Service。

## 3. 可信上下文与消歧

- 用户身份、租户和日期由中端生成；
- 浏览器选择的账户/月度只是查询上下文，不是授权；
- 联系人、账户、卡片、产品和持有候选使用会话内不透明引用；
- 用户点击候选后，中端解析真实资源并重新校验本人归属和当前状态；
- 最近历史只包含服务端保存的本人用户消息，视为不可信文本；
- 生日任务创建还会确定性检查原始用户历史中是否明确出现事件、完整日期、账户末四位和两项独立金额。

## 4. 私有结果算法

余额、流水、账单、异常、财富和订阅的精确结果不放入模型 ToolMessage。Tool 将结果写入短期本人私有快照，模型只收到种类、完整性或数量等安全摘要；结构化事件把不透明结果 ID 交给前端。前端再用 Token 读取 no-store 结果，中端重验用户和依赖资源。

这保证模型无法转述未见金额，也减少外部模型数据暴露。它不隐藏用户主动写入聊天的普通文字，因此仍要做敏感输入拒绝和用户提示。

## 5. Action 与风险算法

写 Tool 只创建或找回 Action/草稿/任务：

```text
参数与归属校验
  ↓
确定风险 GREEN / YELLOW / RED
  ↓
保存不可变摘要 + request_hash + Idempotency-Key
  ↓
YELLOW：结构化确认
RED：结构化确认 → OTP
  ↓
执行前重新校验状态/余额/版本/限额
  ↓
稳定 Fineract 命令键执行
  ↓
回读核心事实 → SUCCEEDED / FAILED / RECONCILING
```

风险等级由操作类型和确定性金额规则决定。模型不能提交风险级别或把 RED 降为 YELLOW。相同幂等键只能重放相同请求；结果不明不得换键。

## 6. 固定生日 DAG

生日任务不是模型生成的任意图。中端按白名单创建固定节点和边：授权、生日当月两笔资金预留、等待、生日前两天分别释放 Hold、花店/蛋糕店付款和通知。每个节点保存独立金额、商户、执行时间、风险和不可变指纹。

Banking Worker 通过数据库行锁、节点状态和稳定键领取到期节点。暂停不释放 Hold；取消释放未消费 Hold；转账响应不明进入核对；部分成功允许有限重试失败节点、取消剩余任务或人工接管，不自动退款已完成采购。

## 7. 故障语义

- 模型不可用：Run 失败或按可恢复策略重试，不产生假业务结果；
- Fineract 明确拒绝：Action/节点失败，记录稳定错误码；
- Fineract 响应丢失：进入 `RECONCILING`，按 externalId、备注标记或核心引用只读核对；
- Worker 中断：租约到期后恢复未完成 Run/节点；
- SSE 断开：按事件游标重放，不重新提交业务写请求；
- 已持久化 Action/任务后模型转述失败：返回确定性结构化事件，提示资金尚未因此改变。

## 8. 安全熔断算法

敏感输入、Prompt Injection 或确定性权限/伪造引用/幂等滥用生成脱敏安全事件。按用户和 `AGENT_WRITE` 作用域维护 10 分钟滚动窗口；第 5 次后设置 15 分钟锁。写 Tool 在 Service 执行前检查锁，查询和普通页面仍可使用。被锁请求不反复延长计数；新的受控敏感输入可作为新的攻击证据。

## 9. 评估方法

版本化数据集包含六场景 120 条功能样本和 30 条安全样本。真实模型按精确领域集合评分，功能门槛 95%，安全门槛 100%；每次模型或 Prompt 变更全量复跑。确定性后端另用 PostgreSQL 集成测试验证权限、Tool Schema、Action、OTP、并发、幂等、故障恢复和敏感信息边界。模型评分不能替代真实 Fineract 与浏览器验收。
